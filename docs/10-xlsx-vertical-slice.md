# XLSX 纵向切片与安全边界

文档状态：V0.2，桌面复核与安全导出接入基线（2026-08-03）

## 1. 已完成的用户流程

当前 CLI 已跑通完整的 XLSX 脱敏事务：

1. 安全读取 XLSX ZIP 包并验证资源上限和必要 OOXML 部件。
2. 从单元格、公式、批注、隐藏内容、页眉页脚和绘图文字建立任务草稿。
3. 可选递归扫描 `xl/media` 下的 PNG/JPEG，并生成逐图遮罩子任务。
4. 用户可以修改 `selected`、`reviewed`、`replacement` 和图片 `mask_rect`。
5. 仅修改命中的工作簿部件，保留未命中的样式、布局和关系。
6. 清理 Office、关系、绘图描述和 ZIP 容器中的隐私元数据。
7. 对候选副本重新解包，复扫所有文字存储位置和每张嵌入图片。
8. 验证通过后原子落盘；不覆盖原件或已有文件。

任务 JSON 包含工作簿原文、公式、OCR 文本和命中值，应当视为敏感文件。
验证报告只记录位置、类型、检测器和错误码，不回显残留原文。

## 2. 当前支持的内容域

- `t="str"`、共享字符串 `t="s"` 和内联字符串 `inlineStr`。
- 数字形式保存的手机号、证件号、银行卡号等候选值。
- 公式文本及公式缓存值。
- 传统批注文字与批注作者。
- 奇偶页、首页的页眉和页脚。
- 隐藏行、隐藏列和隐藏工作表中的单元格。
- 工作表名称和工作簿定义名称。
- DrawingML 文字以及绘图名称、标题和描述属性。
- `xl/media` 下的 PNG/JPEG 图片。

扫描不依赖工作表是否可见，也不只读取 Excel 当前显示的格式值。长数字使用
OOXML 原始单元格值参与检测，避免界面中的科学计数法造成漏检。

## 3. 替换策略

普通单元格命中后转为 `inlineStr`，保留原单元格的引用、样式 id 和其他
属性。这样不会修改仍被其他单元格引用的共享字符串。已失去引用的共享字符
串内容会被清空，防止用户在 Excel 中看不到、但解压 XLSX 后仍能找回原值。

公式和公式缓存的命中默认设为 `selected: false, reviewed: false`，即使规则
置信度很高也不会无人值守改写。用户确认处理后，系统删除公式和缓存，把
整个单元格替换为同一个普通文本值。公式与缓存的多个选中命中若使用不同
替换值，导出会拒绝，避免产生不确定结果。

工作表名称涉及公式、图表、数据验证和外部引用，当前版本不能证明自动改名
后所有引用都被安全更新。因此名称命中必须人工复核为保留；如果将其设为
选中，导出会明确阻断。定义名称的选中命中会删除整个 `definedName`。

## 4. 输入安全限制

| 项目 | 当前上限或行为 |
| --- | --- |
| XLSX 文件 | 100 MiB |
| ZIP entry 数 | 10,000 |
| 单 entry 解压后大小 | 100 MiB |
| 单 XML 大小 | 20 MiB |
| 总解压量 | 500 MiB |
| 大文件压缩比 | 1,000:1 |
| 路径 | 拒绝重复、绝对、反斜线、NUL 和目录穿越路径 |
| 加密 entry | 拒绝 |
| 压缩方法 | 仅 Stored 和 Deflated |

缺少 `[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、
`xl/_rels/workbook.xml.rels` 或工作表 XML 时拒绝处理。XML 中的 DTD 和
文字节点内 CDATA 不进入宽松解析路径。

## 5. 导出时的隐私清理

- 删除核心、扩展、自定义属性、缩略图和 `customXml/`。
- 删除计算链和打印机设置；Excel 可在打开时重建计算链。
- 批注作者统一改为 `LlaMask`。
- 清空 DrawingML 的名称、标题和描述属性。
- 外部超链接改写为 `about:blank`；其他外部关系拒绝导出。
- 所有 ZIP entry 重新压缩，不继承包注释、文件注释、额外字段或时间戳。

未命中且不属于隐私清理范围的 XML、样式和主题保持原始解压字节；受支持的
嵌入图片会统一去元数据重编码，即使图片内没有检测命中。

## 6. 明确阻断的内容

- VBA 宏、ActiveX 和控件属性。
- `xl/embeddings/` 下的 OLE 或其他嵌入对象。
- 图表及其缓存、透视缓存、查询表、切片器缓存和外部链接。
- 数据连接和除超链接以外的外部关系。
- 线程批注、人员部件和数字签名。
- GIF、TIFF、SVG、WMF、EMF 等尚未支持的媒体格式。

这些功能可能在非可见 XML、二进制缓存或外部目标中保存敏感信息。当前版本
选择拒绝整个导出，不把“无法完整验证”误报为成功。

## 7. 独立验证

候选副本在落盘前执行：

- ZIP 路径、压缩资源、必要 entry 和不支持载荷再次验证。
- 单元格、公式、缓存、批注、隐藏内容、页眉页脚和绘图文字重新提取。
- 每个已选原值在原定位点和共享字符串存储中的残留检查。
- 规则、精确词和已配置本地模型重新运行。
- 用户已明确保留的完整命中值按任务快照排除。
- 关系、绘图描述、Office 属性、被删除部件和 ZIP 注释复核。
- 每个 PNG/JPEG 嵌入图片重新解码并执行 OCR、规则和可选模型复扫。
- 嵌入图片任务与 OOXML 路径、数量、格式的一致性检查。

`passed` 表示当前支持域没有残留、嵌入图片通过复扫且元数据已清理；
`complete` 进一步表示策略启用的所有可选本地模型都实际参与了复扫。

## 8. 回归样本与结果

`fixtures/xlsx/comprehensive.xlsx` 只包含合成数据，覆盖两个工作表、隐藏表、
共享字符串、内联字符串、长数字、公式与缓存、传统批注和页眉。规则基线
得到 10 个预期命中，其中公式与缓存 2 个命中强制待复核。

综合嵌入图片回归另外使用合成身份证图片。端到端结果为 10 个结构化命中、
1 个图片逻辑命中，人工确认公式后共 11 个选中结果，文字和 OCR 目标残留均
为 0。输出工作簿可以由独立电子表格引擎重新导入，两个工作表、隐藏状态、
单元格样式和占位符保持正常。发布前仍需在 Windows/macOS 的 Microsoft
Excel 与 LibreOffice 上扩展真实文件和复杂版式回归。

## 9. 桌面端接入

桌面端已把 XLSX 接到与文本、DOCX、图片和 PDF 相同的 Rust 会话状态机：

- 普通状态和进度事件只返回会话 id、阶段、计数、诊断数和稳定错误码。
- 文字复核沿用命中内容及前后各 80 个 Unicode 字符的边界；界面额外显示
  “工作表 1 · 单元格 B3 · 文本”等安全标签，不返回包内 XML 路径、共享
  字符串索引或整个工作簿。
- 公式与公式缓存的复核决定由 Core 按单元格原子同步；应用后整格转成普通
  文本。工作表名称的应用按钮禁用且 Core 再次拒绝选中，只允许明确保留。
  定义名称会提示应用处理将删除整个名称。
- 内嵌图片只在用户进入逐图复核时重新验证源 XLSX 哈希、图片任务与包内
  entry 映射，再返回受限尺寸的重编码 PNG 和几何框。
- 文字和图片结果共享全局导出门禁。原生保存对话框不会向 WebView 返回路径，
  导出继续使用本章定义的工作簿最小修改、元数据清理和独立残留复扫。
- 未安装 OCR 时，不含媒体的 XLSX 可使用规则扫描；含媒体、非 PNG/JPEG、
  图表/透视缓存、外部数据、宏、ActiveX 或嵌入对象的工作簿会安全阻断。

## 10. 命令

```bash
cargo run -p llamask -- scan-xlsx sample.xlsx --task task.json \
  --policy config/policies/default.json \
  --runtimes config/runtimes/development-ocr-small.json
cargo run -p llamask -- export-xlsx task.json --output sample_已脱敏.xlsx \
  --runtimes config/runtimes/development-ocr-small.json
cargo run -p llamask -- verify-xlsx task.json sample_已脱敏.xlsx \
  --runtimes config/runtimes/development-ocr-small.json
```

无嵌入图片时 `--runtimes` 可省略。有嵌入图片时，扫描、导出和验证必须提供
含同一 OCR 运行项的注册表；扫描还可用 `--ocr-runtime` 选择非默认 OCR id。
