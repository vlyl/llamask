## 1. 开发策略

先验证最危险、最不确定的部分，再建设完整界面。推荐顺序：

1. 证明可以安全地提取和回写各类文件。
2. 证明组合检测比单一 LLM 更可靠。
3. 建立残留验证。
4. 再完成面向普通用户的复核体验。

不建议第一周就搭建完整桌面 UI，也不建议先做模型微调。

首发要求 Windows、macOS 和全部目标格式，但开发仍采用逐个“纵向切片”完成的方式。每个格式必须依次通过解析、检测、编辑草稿、导出和残留验证，不能先做完所有解析器再统一补安全导出。

## 2. 阶段 0：产品决策与样本准备

目标：冻结 MVP 边界，建立可以持续评估的基线。

交付物：

- 固化已确认的双平台和文件格式范围。
- 细化个人、组织、财务和业务敏感数据分类。
- 确定自动处理阈值的默认值和策略配置结构。
- 固化企业首发为单机应用，不建设权限、审批和审计系统。
- 固化 PDF 保真优先、安全栅格化兜底策略。
- 固化可跳过人工复核的批量导出模式。
- 定义一致替换作用域和可逆映射的配置结构。
- 收集或生成不含真实隐私的测试样本。
- 建立实体标注规范。
- 确定开源许可证和模型商用许可要求。
- 按[本地模型选型报告](06-model-selection.md)建立模型评估集。
- 实测并冻结中文信息抽取模型和 Q4 量化方案；继续完成双平台资源预算验证。

退出条件：

- 产品决策记录中的 P0 问题已有结论。
- 至少有覆盖剪贴板、TXT、DOCX、XLSX、PPTX、PDF 和图片的合成样本。
- 每个样本都有预期命中和预期导出结果。
- 中文信息抽取候选已完成对比，不再根据通用排行榜推测脱敏效果。
- 默认模型组合在 16GB Windows 与 Mac 基准设备上满足峰值内存门槛。

## 3. 阶段 1：检测内核原型

目标：通过命令行完成剪贴板/纯文本和图片的检测，不追求完整产品界面。

范围：

- 敏感词典与白名单。
- 手机号、邮箱、身份证件号、银行卡号等规则。
- OCR 文字和坐标提取。
- 轻量 NER。
- 4B LLM 候选复核。
- 统一 Finding 数据结构。

实验要求：

- 分别测试“规则”“NER”“LLM”“组合方案”。
- 记录各实体 Precision、Recall、耗时和峰值内存。
- 验证模型结构化 JSON 输出失败时的降级路径。

退出条件：

- 组合检测方案明显优于仅使用 LLM。
- 普通设备上的峰值内存符合预算。
- 每个命中结果都能说明检测来源。

## 4. 阶段 2：安全导出原型

目标：生成真正脱敏的副本，并验证没有明显残留。

内部实现顺序：

1. 剪贴板、TXT / Markdown。
2. PNG / JPEG。
3. DOCX。
4. XLSX。
5. PPTX。
6. PDF。

以上顺序是工程里程碑，不是对外删减后的格式范围。首个公开版本仍需通过全部格式的发布门槛。

范围：

- 文本占位符替换。
- 图片实心色块。
- OOXML 定位和最小修改。
- PDF 页面分类、安全渲染和元数据清理。
- PDF 对象保留、逐页栅格化回退和干净搜索层重建。
- 嵌入图片处理。
- 文件元数据清理。
- 原子输出。
- 导出后二次提取和复扫。
- 批量任务对失败文件隔离。

退出条件：

- 不修改原文件。
- 导出失败不留下伪成功文件。
- 回归样本能由对应应用正常打开。
- 目标敏感值无法通过搜索、复制、解压和 OCR 找回。

## 5. 阶段 3：桌面 MVP

目标：普通用户不接触命令行即可完成完整流程。

范围：

- 文件拖放。
- 策略选择。
- 扫描进度和取消。
- 文档/图片预览。
- 自动应用策略并生成可编辑草稿。
- 结果筛选和定位。
- 撤销、恢复、修改范围、切换脱敏方式和手动新增。
- 修改前后对比。
- 批量处理相同内容。
- 导出和完成报告。
- 可选跳过复核页的自动批量导出。
- 模型与运行环境离线自检。

退出条件：

- 新用户能在没有培训的情况下完成一次任务。
- 所有关键错误都有可理解的提示。
- 应用在拔掉网络的设备上可以从启动运行到导出完成。
- Windows 与 macOS 对同一测试样本产生语义一致的检测结果。

## 6. 阶段 4：本地学习

目标：产品能适应用户习惯，但保持透明和可控。

范围：

- 保存敏感词和白名单。
- 保存默认脱敏方式。
- 保存文件夹策略。
- 保存一致替换的文件、任务和项目作用域。
- 可选创建独立加密的可逆映射库。
- 展示“系统从我这里学到了什么”。
- 撤销或删除学习结果。
- 导入和导出策略包。

退出条件：

- 用户反馈能在下一任务生效。
- 学习不会静默扩大到用户未授权的策略。
- 删除学习结果后行为恢复。

## 7. 阶段 5：发布准备

范围：

- 离线安装包与模型包。
- Windows 与 macOS 独立构建、签名和安装测试。
- 包签名和完整性验证。
- 崩溃与临时文件恢复。
- 性能回归。
- 安全测试。
- 软件物料清单和第三方许可证。
- 用户说明和风险提示。

退出条件：

- 物理断网安装与运行测试通过。
- 支持矩阵中的测试设备通过。
- 无阻断级文件损坏或敏感信息残留缺陷。
- 可逆映射通过密钥丢失、错误密钥和映射损坏测试。
- 已知限制被明确记录。

## 8. 推荐首个技术里程碑

第一份可运行成果不应是完整桌面应用，而应是一个本地 CLI：

```text
llamask scan sample.docx --policy personal-info
llamask review task-id
llamask export task-id --output sample_已脱敏.docx
llamask verify sample_已脱敏.docx
```

它需要证明：

- 文件能被解析成统一结构。
- 规则和 AI 能产生可定位的检测结果。
- 用户选择可以稳定映射回文件。
- 导出的副本能通过残留验证。

桌面 UI 随后调用同一套核心能力，避免界面和命令行形成两套实现。

进度：文本、PNG/JPEG、DOCX、XLSX、PPTX 和 PDF 已完成该纵向闭环。DOCX 已验证跨 run
定位、页眉页脚/表格/脚注/批注/修订/字段代码、最小 XML 修改、元数据清理
和解压残留扫描，并把 `word/media` 下的 PNG/JPEG 递归接入图片任务；XLSX

## 9. 初步工作拆分

### 工作流 A：文件适配

- 文本编码与偏移。
- DOCX XML 定位。
- XLSX 单元格和共享字符串。
- PPTX 页面、备注、母版和版式。
- 图片加载、坐标和导出。

### 工作流 B：检测

- 类型系统。
- 内置规则和校验器。
- OCR。
- NER。
- LLM 复核。
- 结果合并。

### 工作流 C：安全

- 临时目录。
- 原子写入。
- 日志脱敏。
- 残留验证。
- 恶意输入防护。

### 工作流 D：产品体验

- 策略。
- 任务管理。
- 预览和复核。
- 导出报告。
- 本地学习管理。

## 10. 暂不安排

以下内容不应进入 MVP 主路径：

- 自动微调模型。
- 30B 以上模型。
- 云端同步。
- 多用户服务器部署。
- 所有 Office 边缘功能的一次性完整兼容。
- 人脸、语音、视频同时开发。
- 以自然语言代理代替确定性的文件处理逻辑。
