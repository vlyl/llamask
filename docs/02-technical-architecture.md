# LlaMask 技术架构

文档状态：V0.4，DOCX 文字纵向切片已实现

## 1. 架构目标

系统需要同时满足：

- 无网络依赖。
- 支持多种结构化文件。
- 检测过程可解释、可复现。
- AI 组件可替换，不与某一个模型绑定。
- 文件读写和模型运行发生故障时不损坏原件。
- 能在 16GB 内存的普通个人电脑上运行推荐配置。

## 2. 推荐总体架构

```text
桌面界面
   │
   ▼
任务编排器 ─────── 本地策略与反馈库
   │
   ├── 文件类型适配器
   │      ├── TXT / Markdown / Clipboard
   │      ├── DOCX
   │      ├── XLSX
   │      ├── PPTX
   │      ├── PDF
   │      └── Image
   │
   ├── 内容检测引擎
   │      ├── 词典与白名单
   │      ├── 正则与校验器
   │      ├── NER
   │      ├── OCR
   │      └── Local LLM
   │
   ├── 决策与冲突合并
   │
   ├── 预览与人工复核
   │
   ├── 安全导出器
   │
   └── 残留验证器
```

## 3. 进程划分

推荐使用三个逻辑层：

### 3.1 桌面外壳

候选技术：

- Tauri 2
- React + TypeScript

职责：

- 文件选择和拖放。
- 用户主动发起的剪贴板读取与写入。
- 任务进度。
- 文档与图片预览。
- 自动处理草稿与复核交互。
- 设置与策略管理。

选择 Tauri 的主要原因是安装体积较小，并能利用 Rust 处理文件、进程和安全边界。

### 3.2 核心服务

推荐：

- Rust 负责任务状态、文件安全、哈希、原子写入和进程隔离。
- Python sidecar 负责 OCR、NER 和部分文档解析生态。
- Rust 与模型进程使用标准输入输出上的版本化 JSON 请求/响应通信。

MVP 不建议默认启动本地 HTTP 服务，避免监听端口和不必要的攻击面。

文本原型已经采用单次请求/响应的标准输入输出 sidecar 协议。每个请求包含
协议版本、唯一请求编号、Unicode scalar 偏移单位、原文和已有候选；响应
只能返回原文中存在的精确 span。核心服务会重新核对请求编号、边界、原文、
置信度和响应大小，非法响应整批拒绝。详细契约见
[策略与模型进程协议](08-policy-and-sidecar-protocol.md)。

图片原型使用同一进程边界但采用独立 OCR 消息：请求只传绝对图片路径、
预期 SHA-256、请求编号和 OCR 运行项；响应返回源哈希、原始宽高、文字、
置信度、矩形和多边形。Rust 核心独立校验哈希、尺寸、坐标、行数和响应
上限，模型进程不能写图片。当前模型加载日志只允许进入标准错误，协议
标准输出保持为单一 JSON。

### 3.3 模型运行时

- LLM：`llama.cpp` / GGUF。
- OCR：PaddleOCR 或经验证的 ONNX 导出模型。
- NER：ONNX Runtime 或轻量本地推理框架。

模型运行时必须在任务结束后允许卸载，以释放内存。

## 4. 统一文档中间表示

不同文件格式应转换为统一的 `DocumentGraph`，但导出时仍回写原格式，而不是从纯文本重建整个文档。

建议的数据结构：

```text
Document
├── source metadata
├── parts[]
│   ├── kind: paragraph | cell | shape | image | note | metadata
│   ├── locator: 格式专用的稳定位置
│   ├── text
│   ├── style reference
│   └── children[]
├── media[]
└── findings[]
    ├── entity type
    ├── text span 或 bounding box
    ├── confidence
    ├── detector source
    ├── explanation
    └── requested action
```

要求：

- `locator` 能准确映射回原文件节点。
- 文本偏移统一使用 Unicode code point 或 UTF-16，并在接口中明确，禁止混用。
- 图片坐标保存原图像素坐标，同时记录预览缩放矩阵。
- 原文只在内存和任务临时区中存在，不进入普通日志。

## 5. 检测流水线

### 5.1 第一阶段：确定性候选

- 用户敏感词典。
- 白名单。
- 正则。
- 身份证、银行卡等校验算法。
- 文件元数据检查。

优点是快、稳定、容易解释，应最先运行。

### 5.2 第二阶段：统计模型

- NER 检测人名、地点、组织等实体。
- OCR 返回文字、置信度和文字框。
- 可选条形码/二维码解码。

### 5.3 第三阶段：LLM 复核

只向模型提供必要的局部上下文和候选项，要求输出固定 JSON：

```json
{
  "candidate_id": "c-123",
  "sensitive": true,
  "entity_type": "PROJECT_CODE",
  "confidence": 0.91,
  "reason_code": "MATCHES_USER_POLICY"
}
```

原则：

- 模型不能直接修改文件。
- 模型不能自由生成坐标。
- 解析失败时不得把自由文本当成有效决定。
- 低置信度结果进入人工复核。
- 同一模型版本、策略版本和推理参数应尽量产生可复现结果。
- 长文档分块处理，相邻块保留少量重叠，不使用超长上下文硬塞整份文件。

### 5.4 冲突合并

冲突处理优先级建议：

1. 用户手动标记。
2. 精确敏感词典和经过校验的规则。
3. 高置信度结构化识别。
4. NER。
5. LLM 建议。

重叠结果应合并为不会残留字符的最大安全范围，同时在界面中保留原始检测依据。

## 6. 文件格式策略

### 6.1 剪贴板

- 只在用户点击“从剪贴板粘贴”时读取。
- 只处理纯文本，不后台监听剪贴板变化。
- 脱敏结果先显示在任务草稿中，由用户点击后写回剪贴板。
- 剪贴板原文不写入任务日志或长期存储。

### 6.2 TXT 和 Markdown

- 记录原编码、换行符和 BOM。
- 按从后向前的顺序应用文本替换，避免偏移变化。
- Markdown 需要区分可见文本、链接地址、图片地址、代码块和 front matter。
- 策略决定代码块是否扫描，默认扫描但不自动改写。

### 6.3 Office Open XML

DOCX、XLSX、PPTX 本质上是 ZIP + XML，但不能简单转纯文本再重建。

推荐：

- 复制源文件到任务临时目录。
- 只修改包含命中内容的 XML 节点和媒体文件。
- 未修改的 ZIP entry 原样保留。
- 防止 ZIP Slip 和压缩炸弹。
- 导出后检查 XML、关系引用和内容类型。

DOCX 需关注：

- 正文、表格、页眉页脚。
- 批注、脚注、尾注。
- 文本框和超链接。
- 文档属性和嵌入图片。
- 一个词被拆分到多个 run 的情况。

当前 DOCX 文字切片已经实现以下安全边界：

- 输入上限 100 MiB、最多 10,000 个 ZIP entry、单 entry 100 MiB、单 XML
  20 MiB、总解压量 500 MiB，并检查重复/越界路径、加密 entry、压缩方法和
  异常压缩比。
- 正文、表格、页眉页脚、脚注、尾注、批注、术语库、图表和关系图文字统一
  映射为 Unicode scalar span；`w:t`、DrawingML 文本、删除修订文字和字段
  代码均参与检测。
- Word 段落内的多个 run 先拼接检测，回写时替换落入第一个相交 run，后续
  相交 run 只删除原命中片段，从而保留段落、表格、样式和未命中内容。
- 重新压缩全部 entry，以清除 ZIP/File 注释、扩展字段和原时间戳；未修改
  entry 的解压后字节保持一致。
- 删除自定义 XML、自定义属性、缩略图和人员元数据，清除文档变量、绘图
  描述和内容控件标签；批注及修订作者/日期改为固定中性值，外部超链接目标
  改为 `about:blank`。
- 导出前独立解包，重新运行目标原值检查、规则和已配置模型，并验证 OOXML
  元数据和包结构；全部通过后才原子落盘。
- 宏、ActiveX、OLE/嵌入对象默认拒绝。嵌入 PNG/JPEG 在递归图片管线接入
  前也拒绝导出，不能以“仅文字已安全”为由放行整个文档。

完整行为和当前限制见 [DOCX 纵向切片与安全边界](09-docx-vertical-slice.md)。

XLSX 需关注：

- 共享字符串和内联字符串。
- 数值、显示格式和公式。
- 工作表名称、批注和超链接。
- 隐藏行列和隐藏工作表。
- 图表文字和嵌入图片。

对于公式单元格，MVP 默认扫描公式文本及缓存显示值，但不直接用占位符破坏公式；检测到风险时要求用户选择替换整格、清空公式或保留。

PPTX 需关注：

- 幻灯片文本框、表格和组合形状。
- 演讲者备注、批注和母版。
- 图表数据标签和嵌入工作簿。
- 嵌入图片和缩略图。
- 同一文本被拆分为多个 run 的情况。

### 6.4 PDF

解析路径按页面分类：

- 原生文字页：提取字符、字体、绘制位置和阅读顺序。
- 扫描页：渲染为图片后执行 OCR。
- 混合页：合并文字层与 OCR 结果，并消除重复候选。

默认使用混合导出策略：

1. 对能够准确定位并安全移除的文字或图形对象执行真正的对象删除，而不是覆盖一个可移除的黑框。
2. 保留未命中区域的字体、矢量图形、链接、页面尺寸和搜索能力。
3. 删除或重写批注、附件、表单值、隐藏层、增量保存历史和不必要的元数据。
4. 对无法确认已经彻底删除敏感对象的页面，自动回退到页面栅格化并烧录遮盖。
5. 可选为栅格化页面重建不包含敏感内容的搜索文字层。
6. 导出结果记录对象保留页和栅格化页，随后执行独立残留扫描。

策略可以强制“全部保真尝试”或“全部安全栅格化”，但默认采用逐页混合模式。安全验证失败时不得为了保真而放行文件。

### 6.5 图片

- 保留原始像素坐标。
- 对 OCR 框增加可配置安全边距。
- 多行实体合并多个框。
- 遮盖后重新 OCR，检查目标文字是否仍能识别。
- 默认去除 EXIF、XMP 和缩略图元数据。
- JPEG 导出需要避免低质量压缩导致文字或遮盖边缘异常。

当前 PNG/JPEG 实现补充约束：

- 输入上限为 50 MiB、单边 20,000 像素、总计 1 亿像素，并限制解码分配。
- 水平/垂直规则文字按 OCR span 和中英文字宽估算片段框；斜体、旋转或
  无法稳定细分的多边形回退为整行框。
- 跨行手机号、证件号和银行卡号可形成一个逻辑命中和多个遮罩矩形。
- PNG 使用无损重编码并保留透明通道；JPEG 使用质量 95 重编码。EXIF 方向
  先应用到像素，避免清理元数据后照片旋转；随后不复制 EXIF、XMP 或内嵌
  缩略图。
- 输出扩展名必须保持 PNG/JPEG 原格式。实心 RGB 颜色、OCR 自动确认阈值
  和安全边距来自任务内的策略快照。

## 7. 导出安全

导出采用事务式步骤：

1. 在任务临时目录生成候选文件。
2. 验证文件结构可打开。
3. 对候选文件重新提取内容。
4. 运行目标值检查和基础敏感信息复扫。
5. 生成安全报告。
6. 原子移动到用户选择的输出目录。

自动批量任务对每个文件执行独立事务。一个文件失败不能撤销已成功的其他文件，也不能把失败文件标记为完成。任务结束后输出成功、拦截和失败三个集合。

如果任何一步失败：

- 不写入最终目标路径。
- 保留不含原文的错误记录。
- 临时文件按安全策略清理。
- 向用户说明失败阶段。

## 8. 本地策略与反馈库

推荐使用 SQLite：

- `policies`
- `policy_rules`
- `sensitive_terms`
- `allow_terms`
- `feedback_events`
- `model_versions`
- `task_summaries`
- `replacement_maps`

敏感词可采用操作系统密钥链保护的数据库密钥进行加密。搜索索引不能以明文泄露敏感词。

策略规则应有版本号。每个任务保存所用策略版本，以便解释和复现。

策略模型至少包含：

- 适用的文件类型和内容区域。
- 启用的敏感信息分类。
- 词典、白名单和上下文条件。
- 检测器阈值。
- 是否自动应用。
- 每一种实体的脱敏动作。
- PDF 安全导出级别。
- 当前策略的继承来源和版本。
- 是否跳过人工复核并直接批量导出。
- 一致替换的作用域。
- 是否启用可逆映射及其密钥引用。

### 8.1 一致替换

一致替换使用标准化实体值生成内部实体标识，然后在配置的作用域内查询替换映射：

- `document`：只在单个文件内一致。
- `task`：同一次批量任务中的所有文件一致。
- `project`：指定项目中的多次任务一致。
- `global`：本机所有匹配策略的任务一致。

默认使用 `task`。`project` 和 `global` 会产生跨文件关联风险，启用时需要明确提示。

### 8.2 可逆恢复

- 默认关闭。
- 开启后保存原值、实体类型、替换值和作用域的加密映射。
- 映射密钥来自用户提供的恢复密钥或操作系统安全存储，不写入策略文件。
- 恢复功能只读取用户主动选择的映射库，不自动扫描其他任务。
- 密钥管理、备份、轮换和错误口令行为需要单独的安全设计与测试。

## 9. 模型配置

详细依据、候选比较和许可证见[本地模型选型报告](06-model-selection.md)，
实测指标和冻结结论见[模型评测与首发冻结结论](07-model-benchmark-results.md)。

### 9.1 默认目标配置

- 语义复核：`Qwen3.5-4B Q4_K_M`，4K～8K 实际工作上下文，非思考模式。
- 中文信息抽取：`SiameseUIE Chinese base`；开发默认已使用受控的 FP32
  ONNX 单图运行格式，发布前完成双平台便携打包与签名验证。
- OCR 默认档：`PP-OCRv6 small`，用于普通页面和快速批量任务。
- OCR 高安全档：`PP-OCRv6 medium`，用于低质量页面和导出前复扫。
- 版面模型：首发默认不安装 `PP-DocLayoutV3`，待真实复杂页面证明必要后再引入。

默认包为三个逻辑模型模块：Qwen、SiameseUIE 和 OCR。OCR 内部包含
文字检测与识别网络及两个质量档位；模型必须顺序或按需加载，不能把
全部权重常驻内存。

默认大模型只处理歧义候选和局部视觉语义，不承担手机号、邮箱等确定性任务，不生成最终打码坐标，也不直接修改文件。

### 9.2 增强配置

- 暂不提供 `Qwen3.5-9B` 默认增强包；只有真实文件集证明组合召回有至少
  3 个百分点的收益时再引入。
- `PaddleOCR-VL-1.6` 只在复杂表格、公式、印章和图表实测证明有必要后评估。
- 8GB 轻量配置默认不运行 Qwen，仅使用规则、SiameseUIE、small OCR 和
  更保守的自动处理策略。
- 首发不默认安装 embedding 模型，不进行本地权重训练。

模型选择以项目自己的中文敏感信息评估集为准，至少测量：

- 各实体类型的召回率和误报率。
- 精确 span/坐标对齐率。
- 结构化输出成功率和重复运行一致性。
- 推理延迟、模型切换耗时和峰值内存。
- 量化前后的准确度变化。
- 对用户规则的遵循程度。

## 10. 离线打包

建议拆分为：

- 核心安装包。
- 默认离线模型包。
- 可选增强模型包。
- 离线更新包。

每个包包含：

- 清单文件。
- 版本和兼容范围。
- SHA-256 校验值。
- 许可证文件。
- 签名。

安装和启动代码不得在模型缺失时自动联网，应显示如何从离线介质导入。

Windows 与 macOS 分别提供离线安装介质。平台相关的模型运行库可以不同，但模型版本、策略语义、Finding 数据结构和验证结果必须保持一致。

## 11. 可测试性

### 11.1 单元测试

- 各类号码和校验位。
- 文本偏移转换。
- 重叠范围合并。
- 图片坐标转换。
- 文件命名和冲突处理。

### 11.2 格式回归

建立包含以下情况的固定样本库：

- 跨 run 的 DOCX 姓名。
- 页眉、批注和文本框。
- XLSX 共享字符串、公式、隐藏表和图片。
- 旋转、低对比度和多行图片文字。
- Unicode、emoji、中英文混排。

### 11.3 安全测试

- ZIP Slip。
- 压缩炸弹。
- 超大图片。
- 损坏的 OOXML。
- 模型输出非法 JSON。
- 磁盘空间不足。
- 任务中途退出。
- 输出文件重名。
- 临时目录残留。

## 12. 技术风险

### 风险 A：Office 格式保真

这是 MVP 最大工程风险之一。直接使用高层库保存文档可能丢失不受支持的扩展内容。应优先采用最小 XML 修改，并建立真实文件回归集。

### 风险 B：AI 漏检

缓解方式：

- 规则和模型组合。
- 高风险类型使用校验器。
- 高召回阈值。
- 人工复核。
- 导出后二次扫描。

### 风险 C：安装体积

缓解方式：

- 4B 默认、8B 可选。
- 共用运行库。
- 模型包独立升级。
- 不重复存放量化模型。

### 风险 D：用户误以为绝对安全

缓解方式：

- 清楚显示残留检查范围。
- 高风险任务强制展示复核摘要。
- 不使用“100%安全”等不可验证表述。

### 风险 E：跨文件一致替换造成关联

缓解方式：

- 默认只在当前任务内一致。
- 项目级和全局级一致替换明确显示关联风险。
- 可随时新建映射命名空间，避免不同接收方共享相同代号。

### 风险 F：可逆映射成为敏感数据集中点

缓解方式：

- 默认关闭。
- 映射库独立加密。
- 密钥与数据分离。
- 不在普通备份和任务报告中包含映射内容。
