# DOCX 纵向切片与安全边界

文档状态：V0.3，桌面复核与安全导出接入基线（2026-08-03）

## 1. 已完成的用户流程

当前 CLI 已跑通一个完整的 DOCX 文字脱敏事务：

1. 安全读取 DOCX ZIP 包并验证资源上限。
2. 从所有已支持文字域建立可编辑任务草稿。
3. 使用规则、用户精确词和可选本地模型生成命中。
4. 用户可以修改 `selected`、`reviewed` 和 `replacement`。
5. 仅修改命中对应的 OOXML 文本节点，并生成新副本。
6. 清理文档、人员、关系和 ZIP 元数据。
7. 对内存中的候选副本重新解包、提取和复扫。
8. 验证通过后原子落盘；不覆盖原件或已有文件。

包含 PNG/JPEG 时，扫描阶段还会把每个 `word/media` 文件建立为独立图片
子任务。用户可以在同一个 DOCX 任务 JSON 中修改每张图片的 `selected`、
`reviewed` 和 `mask_rect`；导出阶段复用图片工作流进行实心打码和去元数据
重编码，再把安全副本放回原 OOXML 路径。

任务 JSON 含有文档原文和命中值，属于敏感文件。验证报告只记录位置、
类型、检测器和错误码，不回显残留原值。

## 2. 当前支持的文字域

- 正文和表格单元格。
- 页眉和页脚。
- 脚注和尾注。
- 传统及扩展批注 XML 中的段落文字。
- 修订删除文字 `w:delText`。
- 字段代码 `w:instrText`。
- DrawingML、数学文字和图表值。
- 术语库和关系图文字。

Word 经常把一个逻辑值拆成多个 run。扫描阶段按段落合并 `w:t`、
DrawingML 文本、修订删除文字和字段代码；导出阶段按照原节点边界把命中
映射回去。替换文本放入第一个相交节点并继承其 run 样式，其余相交节点只
删除属于原命中的字符。表格、段落属性、书签、批注锚点和未命中 run 不重建。

## 3. 输入安全限制

| 项目 | 当前上限或行为 |
| --- | --- |
| DOCX 文件 | 100 MiB |
| ZIP entry 数 | 10,000 |
| 单 entry 解压后大小 | 100 MiB |
| 单 XML 大小 | 20 MiB |
| 总解压量 | 500 MiB |
| 大文件压缩比 | 1,000:1 |
| 路径 | 拒绝重复、绝对、反斜线、NUL 和目录穿越路径 |
| 加密 entry | 拒绝 |
| 压缩方法 | 仅 Stored 和 Deflated |

缺少 `[Content_Types].xml`、`_rels/.rels` 或 `word/document.xml` 也会拒绝。
XML 中的 DTD 和文字节点内 CDATA 不进入宽松解析路径，避免未扫描内容。

## 4. 导出时的隐私清理

- 核心属性中的作者、最近修改者、标题、描述、时间和其他值全部移除。
- 扩展属性中的管理者、公司、模板、超链接基址和文档标题集合清空。
- `docProps/custom.xml` 和 `customXml/` 整体删除，同时删除对应关系和内容类型。
- 文档变量、内容控件标签、绘图名称/标题/描述清除。
- 批注及修订的作者、缩写和日期改成固定的 `LlaMask`、`LM` 和
  `2000-01-01T00:00:00Z`，以保持 OOXML 必填属性有效。
- 缩略图和人员部件删除。
- 外部超链接改写为 `about:blank`；其他外部关系因无法保证内容仍可安全
  保真而拒绝导出。
- 所有 ZIP entry 重新压缩，不继承包注释、文件注释、额外字段或源时间戳。

未修改 entry 的解压后内容保持逐字节一致；重压缩的目的是清除 ZIP 容器
元数据，并非从中间文本重新生成整个 Office 文档。

## 5. 明确阻断的内容

- VBA 宏、ActiveX 和控件属性。
- `word/embeddings/` 下的 OLE 或其他嵌入对象。
- 除超链接以外的外部关系。
- GIF、TIFF、SVG、WMF、EMF 等尚未支持安全重编码与 OCR 的媒体格式。

PNG/JPEG 已完成“解包图片—建立子任务—替换媒体—再次验证关系和像素”
编排。扫描时如果未提供 OCR 运行注册表，系统仍会生成文字草稿并给出明确
诊断，但导出会拒绝整个文件，要求用户使用 OCR 配置重新扫描。这样不会把
图片中的潜在敏感信息遗漏为成功。

## 6. 独立验证

候选副本在落盘前执行：

- ZIP 路径、压缩资源和必需 entry 再验证。
- 所有文字域重新提取。
- 每个已选原值的全局残留检查。
- 规则、精确词和已配置本地模型重新运行。
- 用户已明确保留的完整命中值按任务快照排除。
- 核心/扩展属性、自定义数据、人员信息、修订身份、关系和 ZIP 注释复核。
- 每个 PNG/JPEG 嵌入图片重新解码并执行 OCR、规则和可选模型复扫。
- 嵌入图片任务与 OOXML 路径、数量、格式和尺寸的一致性检查。
- 嵌入对象、主动内容和不支持媒体格式计数复核。

`passed` 表示当前支持域没有残留且元数据已清理；`complete` 进一步表示策略
启用的所有可选模型都实际参与了每个文本部分的复扫。未配置可选模型时，
规则验证仍可以通过，但 `complete` 为 `false` 并附带明确诊断。

## 7. 回归样本与验证结果

`fixtures/docx/comprehensive.docx` 由
`evaluation/scripts/generate_docx_fixture.py` 生成，只包含合成数据。样本覆盖：

- 跨三个 run 的手机号及粗体、斜体、下划线样式。
- 身份证号、表格邮箱、页眉合同号和页脚手机号。
- 脚注与批注邮箱。
- 修订删除中的旧手机号。
- 字段代码中的邮箱。
- 作者、批注/修订身份和自定义属性。

当前规则基线得到 9 个预期命中；导出副本通过 ZIP 完整性、目标值残留、
规则复扫和元数据检查。文档可以由 LibreOffice 打开并保持一页、页眉页脚、
表格、脚注和修订布局。仓库 QA 运行时没有 CJK 字体，逐页 PNG 中中文会
显示为缺字框；这不影响 OOXML 文本抽取，但发布前仍必须在安装了中文字体
的 Microsoft Word 和 LibreOffice 上进行双平台视觉回归。

嵌入图片回归使用合成身份证图片：PP-OCR 识别出 1 个图片逻辑命中，导出
后的 DOCX 保持单页布局，图片原位置出现实心遮罩；包内独立 OCR 复扫得到
`embedded_images_checked: 1`、`target_residual_count: 0`。测试数据全部为
生成内容，不含真实个人信息。

## 8. 桌面端接入

桌面端已把 DOCX 接到与文本、图片和 PDF 相同的 Rust 会话状态机：

- 普通状态与进度事件只包含会话 id、阶段、计数、诊断数和稳定错误码。
- 文字复核只返回命中内容、替换值、前后各 80 个 Unicode 字符，以及“正文、
  页眉、批注”等安全内容域标签；绝对路径、OOXML locator 和完整文档不进入
  WebView 状态。
- 内嵌图片只在用户打开逐图复核时从原 DOCX 提取。Core 会重新验证源文件
  SHA-256、图片任务与包内 entry 映射，再返回受限尺寸的重编码 PNG 和几何框。
- 关闭图片复核后会回到原文字复核状态。文字结果和图片逻辑组必须全部确认，
  全局导出按钮才会启用。
- 原生保存对话框不会把目标路径暴露给 WebView。导出继续使用本章定义的最小
  OOXML 修改、媒体重编码、元数据清理和独立残留验证。
- 未安装 OCR 时，不含媒体的 DOCX 可使用规则扫描；含媒体的 DOCX、非
  PNG/JPEG 媒体、嵌入对象、宏或 ActiveX 会在桌面扫描阶段安全阻断。

## 9. 命令

```bash
cargo run -p llamask -- scan-docx sample.docx --task task.json \
  --runtimes config/runtimes/development-ocr-small.json
cargo run -p llamask -- export-docx task.json --output sample_已脱敏.docx \
  --runtimes config/runtimes/development-ocr-small.json
cargo run -p llamask -- verify-docx task.json sample_已脱敏.docx \
  --runtimes config/runtimes/development-ocr-small.json
```

三个命令都可传 `--runtimes`。无嵌入图片时它仍是可选参数；有嵌入图片时
必须在扫描、导出和验证中提供含同一 OCR 运行项的注册表。扫描还可传
`--ocr-runtime` 选择非默认 OCR id，并可传 `--policy`；策略快照会保存在
任务中，导出和验证会拒绝 `policy_id` 与快照不一致的任务。
