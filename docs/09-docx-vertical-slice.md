# DOCX 纵向切片与安全边界

文档状态：V0.1，实现基线（2026-07-31）

## 1. 已完成的用户流程

当前 CLI 已跑通一个完整的 DOCX 文字脱敏事务：

1. 安全读取 DOCX ZIP 包并验证资源上限。
2. 从所有已支持文字域建立可编辑任务草稿。
3. 使用规则、用户精确词和可选本地模型生成命中。
4. 用户可以修改 `selected`、`reviewed` 和 `replacement`。
5. 仅修改命中对应的 OOXML 文本节点，并生成新副本。
6. 清理文档、人员、关系和 ZIP 元数据。
7. 对内存中的候选副本重新解包、提取和复扫。
8. 验证通过后原子落盘；不覆盖原件或已有文件。

任务 JSON 含有文档原文和命中值，属于敏感文件。验证报告只记录位置、
类型、检测器和错误码，不回显残留原值。

## 2. 当前支持的文字域

- 正文和表格单元格。
- 页眉和页脚。
- 脚注和尾注。
- 传统及扩展批注 XML 中的段落文字。
- 修订删除文字 `w:delText`。
- 字段代码 `w:instrText`。
- DrawingML、数学文字和图表值。
- 术语库和关系图文字。

Word 经常把一个逻辑值拆成多个 run。扫描阶段按段落合并 `w:t`、
DrawingML 文本、修订删除文字和字段代码；导出阶段按照原节点边界把命中
映射回去。替换文本放入第一个相交节点并继承其 run 样式，其余相交节点只
删除属于原命中的字符。表格、段落属性、书签、批注锚点和未命中 run 不重建。

## 3. 输入安全限制

| 项目 | 当前上限或行为 |
| --- | --- |
| DOCX 文件 | 100 MiB |
| ZIP entry 数 | 10,000 |
| 单 entry 解压后大小 | 100 MiB |
| 单 XML 大小 | 20 MiB |
| 总解压量 | 500 MiB |
| 大文件压缩比 | 1,000:1 |
| 路径 | 拒绝重复、绝对、反斜线、NUL 和目录穿越路径 |
| 加密 entry | 拒绝 |
| 压缩方法 | 仅 Stored 和 Deflated |

缺少 `[Content_Types].xml`、`_rels/.rels` 或 `word/document.xml` 也会拒绝。
XML 中的 DTD 和文字节点内 CDATA 不进入宽松解析路径，避免未扫描内容。

## 4. 导出时的隐私清理

- 核心属性中的作者、最近修改者、标题、描述、时间和其他值全部移除。
- 扩展属性中的管理者、公司、模板、超链接基址和文档标题集合清空。
- `docProps/custom.xml` 和 `customXml/` 整体删除，同时删除对应关系和内容类型。
- 文档变量、内容控件标签、绘图名称/标题/描述清除。
- 批注及修订的作者、缩写和日期改成固定的 `LlaMask`、`LM` 和
  `2000-01-01T00:00:00Z`，以保持 OOXML 必填属性有效。
- 缩略图和人员部件删除。
- 外部超链接改写为 `about:blank`；其他外部关系因无法保证内容仍可安全
  保真而拒绝导出。
- 所有 ZIP entry 重新压缩，不继承包注释、文件注释、额外字段或源时间戳。

未修改 entry 的解压后内容保持逐字节一致；重压缩的目的是清除 ZIP 容器
元数据，并非从中间文本重新生成整个 Office 文档。

## 5. 明确阻断的内容

- VBA 宏、ActiveX 和控件属性。
- `word/embeddings/` 下的 OLE 或其他嵌入对象。
- 除超链接以外的外部关系。
- 当前包含 PNG/JPEG 嵌入图片的 DOCX。

最后一项是暂时性安全门。现有图片切片已经具备 OCR、可编辑矩形、打码和
OCR 复扫，但 DOCX 媒体还需要增加“解包图片—建立子任务—替换媒体—再次
验证关系和像素”的编排。完成前，系统会在扫描任务中给出明确诊断，并在
导出时拒绝整个文件，不会把图片中的潜在敏感信息遗漏为成功。

## 6. 独立验证

候选副本在落盘前执行：

- ZIP 路径、压缩资源和必需 entry 再验证。
- 所有文字域重新提取。
- 每个已选原值的全局残留检查。
- 规则、精确词和已配置本地模型重新运行。
- 用户已明确保留的完整命中值按任务快照排除。
- 核心/扩展属性、自定义数据、人员信息、修订身份、关系和 ZIP 注释复核。
- 嵌入图片、嵌入对象和主动内容计数复核。

`passed` 表示当前支持域没有残留且元数据已清理；`complete` 进一步表示策略
启用的所有可选模型都实际参与了每个文本部分的复扫。未配置可选模型时，
规则验证仍可以通过，但 `complete` 为 `false` 并附带明确诊断。

## 7. 回归样本与验证结果

`fixtures/docx/comprehensive.docx` 由
`evaluation/scripts/generate_docx_fixture.py` 生成，只包含合成数据。样本覆盖：

- 跨三个 run 的手机号及粗体、斜体、下划线样式。
- 身份证号、表格邮箱、页眉合同号和页脚手机号。
- 脚注与批注邮箱。
- 修订删除中的旧手机号。
- 字段代码中的邮箱。
- 作者、批注/修订身份和自定义属性。

当前规则基线得到 9 个预期命中；导出副本通过 ZIP 完整性、目标值残留、
规则复扫和元数据检查。文档可以由 LibreOffice 打开并保持一页、页眉页脚、
表格、脚注和修订布局。仓库 QA 运行时没有 CJK 字体，逐页 PNG 中中文会
显示为缺字框；这不影响 OOXML 文本抽取，但发布前仍必须在安装了中文字体
的 Microsoft Word 和 LibreOffice 上进行双平台视觉回归。

## 8. 命令

```bash
cargo run -p llamask -- scan-docx sample.docx --task task.json
cargo run -p llamask -- export-docx task.json --output sample_已脱敏.docx
cargo run -p llamask -- verify-docx task.json sample_已脱敏.docx
```

三个命令都可传 `--runtimes`。扫描还可传 `--policy`；策略快照会保存在任务
中，导出和验证会拒绝 `policy_id` 与快照不一致的任务。
