# LlaMask 策略与本地模型进程协议

文档状态：V0.3，检测器与 PDF 工具运行包契约已经实现

## 1. 策略配置

默认策略位于 `config/policies/default.json`，策略版本为 1。它可以配置：

- 每类敏感信息是否检测。
- 每类信息是否允许自动处理。
- 每类信息的替换内容。
- 全局自动处理置信度。
- Markdown 代码块是扫描后交给人工确认，还是不扫描。
- 每个模型检测器是否启用、是否为必需、优先级和最低置信度。
- 精确敏感词及其实体类型。
- 按完整命中值生效的白名单。
- 图片实心 RGB 颜色、OCR 自动确认阈值和像素安全边距。
- 一致替换的作用域、可逆恢复开关和密钥引用。

当前只执行普通占位符替换。`project/global` 持久映射和可逆恢复尚未实现，
核心会拒绝这些配置，避免界面显示已启用但导出时被静默忽略。

默认模型检测器是可选的：缺失或异常时保留规则结果，并在任务草稿
`diagnostics` 中记录降级。将检测器设为 `required: true` 后，缺失或失败
会拦截扫描。

任务草稿 schema 版本现为 3。每个命中包含独立的 `selected` 和 `reviewed`
状态：低于自动处理门槛的模型结果保持待复核，用户必须明确选择处理或保留
后才能导出。

图片使用独立的任务 schema 版本 1。一个逻辑实体可能跨越多条 OCR 行；
这些遮罩矩形共享 `group_id`。每个矩形保存原 OCR 框、最终 `mask_rect`、
本行 Unicode span 和完整逻辑命中，后续桌面复核界面可直接修改最终矩形。

## 2. 导出后独立复扫

导出与单独验证命令可以再次传入运行注册表。核心会先检查所有选中原值是否
仍存在，再用策略快照重新运行确定性规则、精确词典和可用模型检测器。

- 用户已经明确保留的 `reviewed=true, selected=false` 结果不会被误拦。
- 替换内容如果形成新的手机号、邮箱等敏感模式，复扫会阻止写出文件。
- `complete=false` 表示某个可选模型没有参加复扫；原因写入通用诊断。
- 验证报告只记录类型、位置、检测器和原因码，不回显敏感原文。
- 必需模型缺失、存在待复核结果或发现新残留时，导出失败且不留下半成品。

## 3. 运行注册表

模型可执行程序不写进脱敏策略，而是放在独立的运行注册表中：

```json
{
  "schema_version": 1,
  "detectors": [
    {
      "id": "siamese_uie",
      "kind": "information_extraction",
      "executable": "sidecars/siamese-uie",
      "working_directory": ".",
      "args": [],
      "assets": [
        {
          "path": "models/weights.bin",
          "sha256": "64位十六进制SHA-256"
        }
      ],
      "timeout_ms": 30000
    }
  ],
  "tools": [
    {
      "kind": "pdfinfo",
      "executable": "pdf/bin/pdfinfo",
      "sha256": "64位十六进制SHA-256",
      "assets": [
        {
          "path": "pdf/lib/libpoppler.dylib",
          "sha256": "64位十六进制SHA-256"
        }
      ]
    }
  ]
}
```

相对可执行文件、工作目录和资源路径以注册表文件所在目录为基准。核心在
启动模型或注册工具前以流式方式校验 SHA-256，当前 SiameseUIE 开发配置
已经固定权重、配置和词表。`tools` 是向后兼容的可选字段，允许的 PDF 工具
为 `pdfinfo` 和 `pdftoppm`；工具可执行文件使用自身的 `sha256`，其动态库等
依赖继续放在 `assets`。桌面安装包生成流程见
`docs/14-offline-runtime-packaging.md`。正式安装包还需要验证整包签名；当前
注册表不能单独作为插件信任机制。

## 4. 请求和响应

每个 sidecar 进程只处理一次请求：从标准输入读取一个 JSON，向标准输出
写一个 JSON，然后退出。不得监听本地端口。

请求的重要字段：

- `protocol_version`：当前固定为 1。
- `request_id`：响应必须原样返回。
- `detector_id`：对应策略与运行注册表中的 id。
- `offset_unit`：固定为 `unicode_scalar`。
- `text`：当前文本片段。
- `candidates`：规则或高优先级模型已经找到的候选。

响应中的每个命中必须提供 `start`、`end`、`matched_text`、实体类型、
置信度和稳定的 `reason_code`。核心程序会执行：

1. 验证协议版本和请求编号。
2. 验证置信度是 0 到 1 的有限数。
3. 验证 Unicode 位置非空且没有越界。
4. 按位置从原文取值，必须与 `matched_text` 完全一致。
5. 应用该检测器和全局策略的两层置信度门槛。
6. 按策略优先级合并；确定性规则始终先于模型结果。

任一步失败都会拒绝该模型的整批响应。错误信息和任务诊断不包含原文。

OCR 使用独立 schema：`schemas/ocr-sidecar-request.schema.json` 与
`schemas/ocr-sidecar-response.schema.json`。请求不把图片内容放在命令行，
而是通过标准输入提供绝对路径与预期 SHA-256。响应返回：

- 原图 SHA-256、宽度和高度。
- 每行文字及 0～1 置信度。
- 原图像素坐标下的 `[x0, y0, x1, y1]` 与多边形。

Rust 核心再次验证源哈希、1 亿像素上限、每个坐标是否落在原图内、文本和
行数上限；任何一项异常都拒绝整批 OCR 输出。图片导出后使用同一 OCR
运行项重新识别候选副本，再运行目标原值检查、规则和可选文本模型。

## 5. 进程约束

- 默认超时范围为 100 毫秒到 10 分钟，超时后终止子进程。
- 标准输出最大 1 MiB，标准错误只读取前 8 KiB，避免无界内存增长。
- 启动时设置 Hugging Face、Transformers、ModelScope 和 Paddle 的离线
  环境变量，并移除常见代理变量。
- 环境变量不能阻止恶意程序直接联网。正式桌面版仍需通过进程沙箱和操作
  系统网络权限形成真正的断网边界。
- 模型进程不能修改文件，只能返回候选；最终修改和导出由 Rust 核心执行。

## 6. 下一步

SiameseUIE 已导出为单文件 FP32 ONNX，并由只依赖 ONNX Runtime、NumPy
和本地 WordPiece 词表的 sidecar 接入；冻结子集 360 条预测与 PyTorch
原评测逐条一致。当前剩余工作：

1. 在 Windows x64 和 Apple Silicon 目标机验证 SiameseUIE ONNX 算子、
   速度、内存和便携运行时，并增加签名与许可证清单。
2. 将当前 Qwen 单记录 sidecar 改为持久工作进程和稳定批处理，复跑全部
   360 条冻结子集并消除与原评测路径的语义漂移。
3. 已增加运行包生成与逐文件哈希契约；下一步补可执行文件签名、许可证和
   兼容版本验证。
4. 缓存同一应用会话中已经验证且文件元数据未变化的大模型哈希，避免每个
   文本片段重复读取数 GB 权重。
5. 在 16GB Windows x64 与 Apple Silicon 设备测试峰值内存和超时降级。
6. 把一次一进程的 OCR/NER 调用改为受控持久进程，减少每张图片重复加载
   模型的启动时间，同时保留超时、请求隔离和内存回收能力。
7. 为图片任务增加桌面预览与矩形拖拽复核，并用真实拍照、旋转文字、印章
   遮挡和超长页面验证整行安全回退。
